# خطة ترحيل أساس التشغيل من play إلى NANE

## القرار
المستودع القديم `aboudalshikhyossef-boop/play` مصدر للبنية التشغيلية فقط. المستودع الجديد يبدأ بقاعدة بيانات جديدة وهوية جديدة، ولا ينسخ اللعبة القديمة كاملة.

## ما نعيد استخدامه
- `server/store.py`: SQLite للغرف واللاعبين والمقاعد والاستعداد والجلسات. نقلناه مع تسمية NANE ومسار تخزين جديد.
- منطق عام مختار من `server/app.py`: HTTP على المكتبة القياسية، قراءة JSON محدودة، Cookie آمنة، فحص Origin، رؤوس حماية، rate limiting وتقديم الملفات. أعيدت كتابة التطبيق دون MatchEngine قديم.
- `scripts/start_chaos_tunnel.sh`: فكرة تشغيل الخادم ثم cloudflared والإغلاق المنظم. أعدنا كتابة سكربت مستقل `start_nane.sh`.
- `compatibility/index.html`: أداة فحص الاتصال واللمس والـ viewport وتدفق الرسائل؛ أعيد تصميمها لهوية NANE.
- `tests/test_store.py`: اختبارات الغرف والمقاعد والتزامن والجلسات؛ تم نقلها وتسمية NaneStore.

## ما لا ننسخه
- `server/engine.py` و`server/challenges.py`: منطق العملات والسرقة والأحداث والتحديات القديمة.
- واجهة `web/index.html` و`web/js/app.js` و`web/css/main.css` القديمة: كانت مرتبطة بمباراة CHAOS القديمة.
- اختبارات المحرك وعقود واجهة الفوضى القديمة.
- قاعدة بيانات المشروع السابق أو بيانات اللاعبين أو رموز الجلسات والغرف.

## بنية المشروع الجديدة
- `server/store.py`: الغرف والجلسات، ثم مخازن مستقلة للملفات الشخصية والمباريات.
- `server/app.py`: HTTP routing والتحقق من الهوية والمدخلات؛ لا يحتوي قواعد اللعبة.
- `server/content/`: بنك الأسئلة وقوالب الرسائل (المرحلة الثانية).
- `server/game/`: محرك المباراة والمراحل والنقاط (المرحلة الثالثة).
- `web/`: واجهة NANE الجديدة فقط.
- `tests/`: اختبارات store وHTTP وcontent وgame وعقود الواجهة.

## الاتصال
Python يربط على `127.0.0.1:8765`، وCloudflare Quick Tunnel ينشئ HTTPS مؤقتًا. جميع الأجهزة تفتح الرابط نفسه وتتصل بخادم واحد وقاعدة SQLite واحدة على اللابتوب. لا يلزم port forwarding أو hotspot، ولا يقوم السكربت بتعديل VPN أو Kill Switch أو UFW.

قاعدة NANE الافتراضية: `~/.local/share/nane-family/nane.sqlite3`. لا تُنقل قواعد البيانات القديمة. رابط Quick Tunnel عام ومؤقت، وليس مصادقة بحد ذاته.

## شروط اعتماد النقل
كل جزء منقول له اختبارات NANE الخاصة به. نجاح اختبارات المشروع القديم لا يُحتسب تلقائيًا نجاحًا في الجديد، وتوافق Safari/Android يجب إعادة اختباره فعليًا على الواجهة الجديدة.
