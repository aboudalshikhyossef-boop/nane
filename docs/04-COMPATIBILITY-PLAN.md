# خطة توافق الأجهزة والاختبار الفعلي

## الأجهزة المستهدفة
- Linux Mint laptop: يستضيف الخادم المحلي واللاعب الأول يفتح نفس رابط النفق.
- هاتفان Android.
- iPhone 4S يعمل بـ iOS 9.3.6 وSafari القديم.

## قيود التطوير
- أقل عرض مستهدف: 320 CSS px.
- واجهة عربية RTL ونصوص لا تتجاوز الحاويات.
- JavaScript محافظ: `var` ودوال تقليدية وXMLHttpRequest؛ تجنب Fetch وasync/await وميزات حديثة لا يدعمها Safari 9.
- CSS دون CSS Grid؛ استخدام Flexbox بحذر وبدائل بسيطة.
- لا خطوط خارجية أو CDN مطلوب لتشغيل اللعبة.
- أهداف لمس واضحة وأزرار ذات ارتفاع عملي.
- جميع المتصفحات تتصل بخادم واحد؛ لا اتصال مباشر بين الهواتف.

## فحص /compatibility
يعرض صفحة تشخيص منفصلة:
- صحة اتصال الخادم عبر `/api/health`.
- قياسات viewport واكتشاف التجاوز الأفقي.
- استجابة زر اللمس.
- إرسال رسالة تشخيص مؤقتة إلى الخادم وظهورها في feed على الأجهزة الأخرى.
لا تستخدم هذه الصفحة للمحادثات أو للبيانات السرية، ولا تُعد جزءًا من واجهة اللعب.

## قائمة اختبار القبول
1. فتح الصفحة الرئيسية ونجاح `/api/health` من الأجهزة الأربعة.
2. إنشاء غرفة من اللابتوب والانضمام من Android وiPhone.
3. ظهور المقاعد والحالات بنفس الترتيب على الجميع.
4. استعداد ثلاثة لاعبين ثم أربعة والتحقق من حالة الغرفة.
5. تحديث صفحة لاعب والتحقق من استعادة المقعد والجلسة نفسها.
6. قطع الاتصال مؤقتًا ثم العودة دون إنشاء مقعد مكرر.
7. تجربة 320px و360px و390px والاتجاهين العمودي والأفقي.
8. اختبار اللمس والتمرير والنسخ/إدخال رمز الغرفة.
9. إرسال رسالة من الهاتف وظهورها في صفحة التشخيص على اللابتوب.
10. بعد اكتمال اللعبة: مباراة كاملة بثلاثة لاعبين وأخرى بأربعة، مع التأكد من سرية الإجابات والكشف والنقاط.

## ما الذي تثبته الاختبارات؟
- اختبارات الوحدات تثبت قواعد المخزن والمحرك.
- اختبارات HTTP تثبت سلوك الخادم والكوكيز والصلاحيات.
- GitHub Actions يثبت أن الاختبارات وفحوص المصدر نجحت في CI.
- الاختبار الفعلي وحده يثبت سلوك Safari 9 وAndroid وCloudflare على الأجهزة المستهدفة.
لا نسجل نجاح جهاز قبل اختباره عليه فعلًا.
